# req-analyze-requirements

## Description
This skill analyzes raw, unstructured requirements and transforms them into clear, organized, and actionable design requirements. It identifies ambiguities, gaps, and conflicts within the provided requirements and surfaces them for resolution. It also categorizes requirements by type (functional, non-functional, accessibility, brand) and prioritizes them to help the design team focus on what matters most.

## Intake
- Raw requirements text (brief, email thread, meeting notes, stakeholder feedback, or any unstructured input)
- Project context (product area, target users, platform)
- Any existing constraints or known dependencies (optional)

## Expected Output
- A structured requirements document organized by category (functional, non-functional, accessibility, brand/visual)
- A prioritized list of requirements (must-have, should-have, nice-to-have)
- A list of identified ambiguities or gaps that need stakeholder clarification
- A list of conflicting requirements flagged for resolution
- A summary of key design decisions implied by the requirements

## When to Use
Use this skill at the **start of any design project or feature work** when you have gathered raw input from stakeholders and need to organize it into something actionable for the design team. It is especially useful when:
- Requirements come from multiple sources and need to be consolidated
- The brief is vague or incomplete
- You need to communicate back to stakeholders what is understood and what still needs clarification
- You need to scope design work for sprint planning
